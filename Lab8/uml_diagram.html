Design and multiplicities

Supplier–Product: each product refers to exactly one supplier; a supplier may supply zero or more products. The supplier is created independently and is not a part of the product.

Inventory–Product: each inventory contains zero or more products. The current implementation permits a product in zero or more inventories, so the Inventory end is 0..*. Section 3 demonstrates transferring a product; enforcing exclusive membership would require an additional rule and a 0..1 multiplicity instead.

Order–OrderLine: each line belongs to one order; an order creates and manages zero or more lines. Lines are not intended to be transferred or managed independently. Public Python lists do not enforce that design constraint.

OrderLine–Product: each line refers to exactly one product; a product may be referenced by zero or more lines. Removing a line does not destroy its product.

Types: String, Integer, Real, Boolean and void represent Python str, int, float, bool and None. Product [0..1] represents Product | None. Map<String, String | Real | Integer> represents the saved product dictionary. Constructors are shown as «create» operations; inherited members are omitted from subclasses. Italics mark abstract operations.

Implementation note: Inventory currently declares show_product_details without self or @staticmethod. It is shown with its declared parameter in the diagram; calling it through an inventory instance requires fixing that signature. The separate polymorphism test uses a standalone helper.
